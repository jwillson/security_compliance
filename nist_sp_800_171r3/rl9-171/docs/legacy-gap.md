## Consequences worth restating

- Multi-factor authentication is `03.05.03`. The extraction puts it at
  `03.05.02`, which in r3 is Device Identification and Authentication.
- `03.14.07` is withdrawn. The archived playbook uses it for AIDE;
  file integrity monitoring belongs under `03.14.06` System Monitoring.
- `03.13.11` is Cryptographic Protection, not Session Authenticity
  (`03.13.15`). The nginx snippet in `web/` cited the wrong one.
- `google-authenticator` is not FIPS 140-3 validated, so it does not
  satisfy `03.05.03` on a host running in FIPS mode.
- The archived playbook POSTs telemetry to a placeholder URL. No r3
  requirement asks for that.
